= Oracle Cloud Infrastructure에서 리소스 삭제

Oracle Cloud Infrastructure에서 더 이상 사용하지 않는 리소스를 삭제하는 것은 비용 낭비를 막고 인프라를 깔끔하게 유지하기 위한 필수 작업입니다. OCI는 엔터프라이즈 환경에 맞추어 설계되었기 때문에, 리소스 간의 종속성과 물리적 삭제 정책이 명확하게 구분되어 있습니다.

== 리소스 삭제의 기본 원칙: 종속성(Dependency)

OCI의 가장 중요한 규칙은 "자식 리소스나 연결된 리소스가 남아있으면 리소스를 삭제할 수 없다"는 점입니다.

* **예시(VCN 삭제)**: 가장 네트워크(VCN)를 삭제하고 싶다면, 그 VCN 안에 만들어진 컴퓨트 인스턴스, 로드 밸런서, 서브넷 등을 먼저 전부 삭제해야만 최종적으로 VCN을 삭제할 수 있습니다.
* **강제 삭제 불가**: 부모 리소스를 다 지운다고 해서 하위 리소스들이 자동으로 일괄 삭제(Cascade Delete) 되지 않는 경우가 많습니다. 인프라를 처음부터 하나씩 역순으로 걷어내야 합니다.

== 리소스별 삭제와 용어와 상태(Termology)

OCI 콘솔이나 API에서 리소스를 제거할 때, 리소스의 종류 따라 사용하는 단어와 내부 처리 방식이 다릅니다.

=== Terminate (종료/폐기)

* **대상**: Compute Instance, Autonomous Database 등
* **특징**: 리소스를 영구적으로 삭제할 때 사용합니다. Terminate를 수행하면 가상 머신이 정지되고 물리적 자원이 회수됩니다.
* **상태 변화**: 상태가 `TERMINMATING` 으로 바뀌고, 처리가 끝나면 `TERMINATED` 상태로 콘솔에 잠시 남아 있다가 수 시간 내에 목록에서 완전히 사라집니다.

=== Delete (삭제)

* **대상**: VCN, Block Volume(스토리지), Object Storage Bucket, Security List 등
* **특징**: 네트워크 컴포넌트나 저장 장치, 데이터 자산을 지울 때 주로 사용합니다. Delete 즉시 자원이 삭제되거나 휴지통 개념의 유예 기간을 거치게 됩니다.

=== Detach (분리) vs Destroy (파괴)

* **Detach**: 컴퓨트 인스턴스에 붙어있는 블록 볼륨(외장 하드)을 서버에서 떼어내는 것을 의미합니다. 데이터는 그대로 살아있으며, 서버와의 연결만 끊어집니다.
* **Destroy**: 주로 Terraform(OCI Resource Manager)을 사용할 때 쓰는 용어로, 코드로 생성한 모든 인프라 자원을 한 번에 밀어버릴 때 사용합니다.

== 완전 삭제 전 유예 기간: 보호 장치

실수로 데이터를 날리는 것을 방지하기 위해 OCI는 몇 가지 보호 장치를 제공합니다.

* **Object Storage Lifecycle**: 오브젝트 스토리지의 버킷이나 객체는 삭제 시 즉시 사라질 수 있지만, '보존 정책(Retention Policy)'을 걸어두면 관리자라 할지라도 일정 기간 동안 절대 삭제할 수 없도록 강제할 수 있습니다.
* **Block Volume 백업**: 인스턴스를 Terminate할 때, "부착된 부트 볼륨도 함께 지우겠습니까?"라는 체크박스가 뜹니다. 이때 체크를 해제하면 서버 본체는 사라져도 데이터가 담긴 디스크(Boot Volume)는 남아있어 나중에 다른 서버에 붙여 데이터를 살릴 수 있습니다.

== 컴파트먼트(Compartment) 삭제의 특수성

OCI의 독특한 자원 격리 개념인 컴파트먼트를 삭제할 때는 특히 주의해야 합니다.

* 컴파트먼트는 리소스를 담는 '논리적 폴더' 역할을 합니다.
* 컴파트먼트를 삭제하려면 내부에 단 하나의 활성화된 리소스도 남아있지 않아야 합니다. (모든 인스턴스가 `TERMINATED` 상태여야 하며, 모든 서브넷과 VCN이 지워진 상태여야 함)
* 조건을 만족하여 컴파트먼트를 삭제하면 상태가 DELETED로 바뀌며, 이 상태의 폴더는 콘솔에서 완전히 사라지기까지 며칠이 소요될 수 있습니다.
